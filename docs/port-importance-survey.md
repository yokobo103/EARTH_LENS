# 港レンズの表示重要度 — 調査

2026-09-13 / 調査と Phase 1（container 軸）の実装。bulk / energy は未着手。

## 現状の実測

### データ

`public/geo/major-ports.geojson` — Natural Earth 1:10m Ports、**1,081 点**。

属性は6つだけで、Natural Earth の元ファイルと完全に同じ。増やせる余地は無い。

```
scalerank   3-8 の6段階
natlscale   scalerank の逆写像（3↔75 / 4↔50 / 5↔30 / 6↔20 / 7↔10 / 8↔5）
featurecla  全1,081点が "Port"
name        港名
website     港湾局のURL
ne_id       Natural Earth の識別子
```

**取扱量も、規模も、国名すら入っていない。** `natlscale` は `scalerank` と同じ情報の別表現で、
独立した2つ目の信号ではない。河川の `strokeweig` が全 null だったのと同じ構図。

```
scalerank 3: 67点   4: 76点   5: 150点   6: 229点   7: 297点   8: 262点
```

（rank≤4: 42,000km / 5: 28,000 / 6: 19,000 / 7: 13,000 / 8: 10,000km）。

同じ縮尺で東アジアは 196 点なので、**世界の物流の中心ほど点が少ない**。

### 小港と巨大港を区別できているか

できていない。点の大きさは `max(4.5, 8 - scalerank × 0.42)` の1本だけで、

```
rank 3 → 6.7 px      rank 8 → 4.5 px
```

**最大でも1.5倍**。しかもその scalerank が取扱量と無関係なので、
上海（rank 4 = 6.3px）より Gythion（rank 3 = 6.7px）の方が大きく描かれている。

## 指標の調査

### 候補と評価

| 指標 | 出どころ | 被覆 | 入手性 | 説明可能性 |
|---|---|---|---|---|
| コンテナ取扱量 TEU | UNCTAD / Lloyd's List / 各港湾局 | 上位100〜150港 | 公表リストはあるが機械可読な一括配布は無い | ◎「年間4,910万TEU」 |
| 総貨物量（トン） | 各国統計・港湾局 | 国ごとにばらばら | 統一フォーマット無し | ◎ ただし比較可能性が低い |
| 寄港船舶数 | AIS（MarineTraffic等） | 全球 | 商用。無償の全球配布は見つからず | ◎ |
| 港湾定期船就航指数 PLSCI | UNCTAD | 900港超・四半期 | UNCTADstat の画面にはあるが、一括取得のURLは 403/404 | ○ 指数なので単位が無い |
| 港湾の物理規模 | **NGA World Port Index** | **3,807港・全球** | **公開・DL確認済み（3.5MB CSV）** | ○「港の規模：大／最大喫水15m」 |

### World Port Index を実際に検証した

NGA の World Port Index を落として、Natural Earth の 1,081 点に位置で結合した。

- 3,807 港、109 列、全港に緯度経度あり、パブリックドメイン
- 使えそうな列: `Harbor Size` / `Harbor Type` / `Maximum Vessel Draft` /
  `Facilities - Container` / `Cranes Container` / `UN/LOCODE` / `Country Code`

**結合そのものは成功した。**

```
許容  5 km:  928 / 1081 (85.8%)
許容 10 km:  983 / 1081 (90.9%)
許容 20 km: 1020 / 1081 (94.4%)
```

`Harbor Size` の分布（許容20km）: Large 122 / Medium 234 / Small 425 / Very Small 222 /
空 17 / 照合なし 61。Large が 122 点で、世界段の規模としては手頃に見える。

**しかし中身が使えない。**

| 港 | 実際の位置づけ | WPI Harbor Size |
|---|---|---|
| 寧波舟山 | 世界3位・35.3M TEU | **Small** |
| ロッテルダム | 欧州最大 | **Very Small**（3.2km先の Maassluis に吸われた） |
| 天津 | 世界8位 | **Very Small**（18.7km先の Dagu Tanggu） |
| ジュベルアリ | 世界11位 | **Small** |
| 深圳（塩田） | 世界4位 | **Small** |
| ラムチャバン | 世界20位 | **Small** |

Large 122 点の顔ぶれには Buffalo・Detroit・Cleveland・Dundee・Brest・Cherbourg が並ぶ。

不調の理由は2つ重なっている。

1. `Harbor Size` は**水面の広さの分類**であって取扱量ではない。しかも更新が古い。
2. 港湾集積は WPI 側でも複数点に割れていて、**最近傍だと隣の小さい点を拾う**
   （ロッテルダム→Maassluis、シンガポール→Jurong Island）。

`Facilities - Container` は 3,807港中 3,233港が Unknown、`Cranes Container` は 3,764港が
Unknown、`Maximum Vessel Draft` は中央値 0.0 m（未入力）。**埋まっていない。**

河川で HydroRIVERS が効いたのは、平均流量という**物理量が全球で一様に計算されていた**から。
港には、それに当たる公開データが無い。

## 設計の方向

### 河川と決定的に違う点

河川: 重い外部データ → オフラインで属性移植 → 99.6%被覆 → 全部説明できる。

港: **一様で正しい外部データが無い。** 使える量（取扱量）は上位100〜150港にしか存在せず、
全球一様の量（WPIの物理規模）は肝心の巨大港を取りこぼす。

なので「全点に一つの指標を付ける」は成立しない。**段ごとに別の根拠を使う**のが現実的。

### 案

| 段 | 根拠 | 出典 | 点数の目安 |
|---|---|---|---|
| 世界 | 年間コンテナ取扱量（＋原油・ばら積みの上位） | 公表リストを1本に整理して焼く | 60〜90 |
| 大陸 | ＋ 取扱量の中位、または WPI Large かつコンテナ施設あり | 同上＋WPI | 200〜260 |
| 国 | ＋ 残り（WPI の規模順） | WPI | 500〜600 |

世界段は 60〜90 点あれば足りる。**上位100港を人手で整理するのは現実的な作業量**で、
1,081点に全部付けるより確実。しかも「年間4,910万TEU」は、
河川の「平均流量800 m³/s以上」と同じ強さで説明できる。

段が進むほど根拠が弱くなるのは避けられないが、**理由を属性に持たせれば説明はできる**
（河川の `displayReason` と同じ）。

```
displayReason "throughput"  年間 4,910万TEU
displayReason "harbour"     港の規模: 大 / コンテナ施設あり（World Port Index）
displayReason "scalerank"   どちらにも当たらない（Natural Earth の既定）
```

### 画面から逆算した点数

実測した画面を見ながらの提案。

| 段 | 高度 | いまの画面 | 提案 |
|---|---|---|---|
| 世界 | 6,000 km 超 | 手前側144点・大小の差なし | **手前側40〜60点**（全球で80〜110点）。大きさは取扱量で3〜4段階 |
| 大陸 | 2,800–6,000 km | 欧州508点・ラベル41 | **画面に80〜120点**、ラベルは上位10〜15枚だけ |
| 国 | 2,800 km 未満 | オランダ436点・ラベル149 | **画面に150〜200点**、ラベルは30枚程度 |

近景で全点に戻さないのは河川と同じ。いまの rank 7・8（559点）の多くは
漁港やマリーナで、「港湾構造」を読む邪魔にしかならない。

### Natural Earth に無い港

**釜山・ポートクラン・タンジュンペラパスは点そのものが無い。** 属性の移植では作れない。

河川では「信濃川が無い」を受け入れたが、港では事情が違う。
**世界上位15港のうち3港が欠けるのは、このレンズの成功条件に直接当たる。**
足すとしても10〜20点なので、河川（273,191 reach）とは桁が違う。

ただし「大河川を個別ハードコードしない」と決めた方針との整合は要相談。
点を足すのは「見え方を決め打ちする」のとは別物だが、線引きは所長判断。

### 未解決

- **コンテナ偏重の危険。** ラスタヌラ（原油）、ヘッドランド港（鉄鉱石）のような
  コンテナを扱わない巨大港がある。取扱量だけだと「石油と鉱石の港」が消える。
  総貨物トン数を併記するか、種別を分けるか。
- **PLSCI の一括取得。** UNCTADstat の画面にはあるが、機械可読な取得経路を見つけられなかった。
  取れるなら、900港・四半期更新・単一指標なので有力候補になる。
- **AIS の寄港数。** 本当は流量にいちばん近いが、無償の全球配布が見つからなかった。

## 複数軸での設計（2026-09-13 追調査）

単一指標にまとめない方針で調べ直した。**World Port Index の Harbor Size は重要度に使わない**
（前節の実測どおり寧波舟山が Small、ロッテルダムが Very Small になる）。
WPI は **LOCODE から座標を引くだけの住所録** として使う。

### 軸ごとの全球データ

| 軸 | データ | 収録数 | 入手 | ライセンス |
|---|---|---:|---|---|
| container | **World Bank / S&P Container Port Performance Index 2024** | **403港** | **確認済み**（xlsx 67KB・UN/LOCODE付き） | CC BY 3.0 IGO |
| container（量） | 世界のコンテナ取扱量ランキング | 約127行・出典218件 | 公表リスト、機械可読 | 各行に出典 |
| bulk / energy（量） | 世界の総貨物量ランキング | 約293行 | 公表リスト、機械可読 | 各行に出典 |
| energy（LNG） | Global Energy Monitor / Global Gas Infrastructure Tracker | LNG基地 1,207件 | **メールフォーム経由**（直リンク無し） | 要確認 |
| energy（石炭） | GEM / Global Coal Terminals Tracker | 522基地・200超の港 | **メールフォーム経由** | 要確認 |
| connectivity | UNCTAD Port Liner Shipping Connectivity Index | 900港超・四半期 | 港単位であることは API で確認。**一括取得の経路は見つからず** | — |
| （住所録） | NGA World Port Index | 3,807港・全球 | 確認済み（CSV 3.5MB） | パブリックドメイン |

CPPI は **順位ではなく名簿として使う**。中身は効率の指数（滞船時間）で、量ではない。
「世界の定期コンテナ網に載っている403港」という名簿としてなら、出典付きで一貫して使える。

### 1つの軸では足りないことの実測

コンテナ取扱量のリストと総貨物量のリストを突き合わせた。
**総貨物量にしか出てこない港が22ある。**

```
ポートヘッドランド（鉄鉱石・豪）  トゥバロン（鉄鉱石・伯）
黄驊・日照・唐山（石炭と鉱石・中） サウスルイジアナ・ヒューストン・ボーモント・
ニューオーリンズ（石油と石化・米） ノヴォロシースク（石油・露） 蔚山（石油化学・韓）
```

**コンテナだけで測ると、鉄鉱石と石油の世界が丸ごと消える。** 軸を分ける根拠はここ。

### Natural Earth に足りない港（実測）

CPPI の403港を、LOCODE → WPI の座標 → Natural Earth の点、の順に照合した。

```
CPPI 403港 → LOCODEで座標が付いた       351港 (87%)
  うち Natural Earth の点に載る(25km以内)  272港
  Natural Earth に無い                    79港
```

無い79港には **釜山・ポートクラン・ジェベルアリ・フェリクストウ・ジェノヴァ・
ジョイアタウロ・コンスタンツァ・アシュドッド・ダンマーム** が含まれる。

補完の基準はこう書ける。

1. **どの外部基準か** — World Bank CPPI 2024 の403港に含まれること
2. **一貫しているか** — その403港のうち、既存の点から25km以上離れている**全て**を足す。
   79港。選ばない
3. **なぜ元データでは足りないか** — Natural Earth の港点は客船寄港地に厚く、
   コンテナ港に薄い。世界上位15港のうち3港が無い

座標は WPI（パブリックドメイン）の LOCODE 引き。出典は港ごとに CPPI + WPI の2件。

### 軸ごとの点数と、段の見積もり

| 段 | container | 総貨物量 | energy | connectivity | 合計の目安 |
|---|---:|---:|---:|---:|---:|
| 世界 | 上位30〜40 | 上位20〜30（重複除く） | LNG・石油の上位15〜20 | — | **60〜90** |
| 大陸 | CPPI 403 の上位150程度 | 上位100 | 主要LNG・石炭基地 50 | PLSCI 上位（取得できれば） | **200〜260** |
| 国 | CPPI 403 全部 | 全部 | 全部 | — | **450〜550** |

前節で実測した画面（世界で手前側144点、欧州の大陸表示で508点、
オランダの国表示で436点・ラベル149枚）に対して、

- 世界段は **手前側40〜60点**に落ちる（全球で60〜90点）
- 大陸段は欧州でも **80〜120点**に収まる
- 国段は **150〜200点**

### 軸をどう見せるか（2026-09-13 決定）

**軸は色にも形にもしない。** 軸が決めるのは2つだけ。

1. **採用判定** — その港をどの段に入れるか
2. **地点カードの説明** — なぜこの港が出ているか

港レンズは単色のまま。軸ごとに描き分けると、レンズ1枚の中に4つの語彙が生まれて、
他のレンズと重ねたときに何を見ているのか分からなくなる。

```
displayTier   1 | 2 | 3            ← 見た目に効くのはこれだけ
displayAxis   "container" | "bulk" | "energy" | "connectivity"
displayValue  4110（万TEU）/ 1260（百万トン）/ 77（MTPA）
displaySource 出典の識別子
```

#### この決定が解く問題

軸を見た目に出さないので、**軸をまたいで大きさを比べる必要が無くなる**。
4,110万TEU と 12.6億トン と 77 MTPA を同じ物差しに載せる方法は無いし、
載せた瞬間に説明できなくなる。

**大きさは段が持つ。** 3段＝3サイズ。段の中では大小をつけない。
世界段に入る60〜90港はどれも本物の巨大港なので、その中の順位付けは要らない。

必要なら「いずれかの軸で世界10位以内」を4つ目のサイズにできる。
これも説明できる（「コンテナ取扱量で世界2位」）。軸をまたいだ計算はしていない。

#### 複数の軸に乗る港

シンガポールは container と energy の両方に乗る。
**順位がいちばん高い軸を代表にして、残りは属性に残す。** 代表が変わっても見た目は変わらない。

```
シンガポール
コンテナ取扱量 4,110万TEU（世界2位）・石油製品の積替拠点
```

1行目が代表軸、2行目以降が残りの軸。地点カードの中だけの話。

### 未解決

- **GEM の2トラッカーはメールフォーム経由**。一度取ればオフライン処理には足りるが、
  自動化はできない。ライセンス条項はダウンロード時に確認が要る
- **PLSCI の一括取得経路が不明**。港単位・四半期・900港超なので、
  取れれば connectivity 軸が一気に固まる
- **総貨物量の年次と定義が国ごとにばらつく**。コンテナTEUほど比較可能性が高くない

## この時点での推奨

1. **WPI を主指標にはしない。** 結合はできるが、肝心の巨大港を Small と評価する。
   補助（大陸・国段の並べ替え）に留める。
2. **世界段は取扱量の公表リストから作る。** 60〜90 点なら人手で整理でき、
   出典も1件ずつ示せる。ここが成功条件に直接効く。
3. **欠けている巨大港を足すかどうかを先に決める。** これが決まらないと、
   どの指標を選んでも「釜山が無い」は直らない。

## Phase 1 の結果（container 軸のみ）

`tools/build-port-importance.py` で焼いた。

```
港 1,164 点（うち補完 83 点）
  世界  50   World Shipping Council Top 50 (2024)
  大陸 310   World Bank / S&P CPPI 2024 の403港のうち座標が引けたもの
  国   804   残り
```

補完した83点。**基準を満たすものは全部足した。選んでいない。**

- 世界段 12点 — Shenzhen / Busan / Jebel Ali / Port Klang / Tanjung Pelepas /
  Suzhou / Guangxi Beibu / Mundra / Cai Mep / Rizhao / Colon / Dongguan
- 大陸段 71点 — Felixstowe / Genoa / Gioia Tauro / Constantza / Ashdod / Dammam ほか

座標は World Port Index（パブリックドメイン）か Wikidata（CC0）から引き、
どちらから引いたかを点ごとに `addedFrom` に残してある。

### 同じ港かどうかの判定

距離だけでは決まらなかった。実測の内訳:

```
タンジュンペラパス  シンガポールの 20.1 km 先  別の港（別の国）      → 足す
天津              既存 Tianjin の 32.8 km 先  同じ港（市街と新港）  → 足さない
深圳              広州の 26.7 km 先          別の港               → 足す
ジェベルアリ        ドバイの 35.5 km 先        別の港               → 足す
```

なので **20 km 以内、または名前が一致して 45 km 以内**を同じ港とした。
この4件はすべて正しく分かれる。
