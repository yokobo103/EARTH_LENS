# 河川の表示重要度 — 調査と設計

2026-09-13 / 調査と実装。案 C を採用して反映済み。

## なぜ

`scalerank` は川の規模ではない。Natural Earth が「どの縮尺の地図でこの線を出すか」を製図の判断で
付けた値で、水の量とは別物。実測すると破綻が出る。

| 川 | NE scalerank | 平均流量（実測） |
|---|---|---|
| トンガリロ川（NZ） | **0**（全世界で最強） | 40 m³/s |
| トゥオトゥオ川（長江源流） | 1 | 28 m³/s |
| マディソン川 | 1 | 24 m³/s |
| 贛江（rank 6） | 6 | 6,037 m³/s |
| バラク川（rank 9） | 9 | 4,840 m³/s |
| オゴウェ川（rank 8） | 8 | 4,581 m³/s |

rank 0 の川は全世界に1本だけあり、それがトンガリロ川（全長100 km 前後）だった。
アマゾン（rank 1）より強い扱いになっている。

収録密度も一様ではない。

```
ニュージーランド 60本（最強rank 0）   フランス 17本   イタリア 13本
イギリス 8本                          日本 3本（石狩・最上・利根のみ）
```

信濃川・千曲川・木曽川・淀川・北上川・天塩川・十勝川は Natural Earth に存在しない。

元データの属性は `dissolve / featurecla / min_label / min_zoom / name / name_alt / name_en /
note / rivernum / scalerank` のみ。**川幅も流量も長さも入っていない**
（`strokeweig` は全1,455本 null）。

## 調べたこと

### HydroRIVERS（HydroSHEDS）

- 全世界 8,477,883 reach、平均 4.2 km、総延長約 3,590 万 km
- 収録基準: 流域面積 10 km² 以上 または 平均流量 0.1 m³/s 以上
- ライセンス: 非商用・商用とも無償。出典表示が必要。
  引用は Lehner, B., Grill G. (2013) *Hydrological Processes* 27
- 配布: 全球 shapefile 544 MB / 地域別 9〜108 MB

使える属性:

| 属性 | 中身 |
|---|---|
| `DIS_AV_CMS` | 長期平均流量 m³/s |
| `UPLAND_SKM` | 上流流域面積 km² |
| `ORD_STRA` | Strahler order |
| `ORD_CLAS` | 古典的次数。**1 = 河口から源流までの本流** |
| `ORD_FLOW` | 流量の対数階級。1 = 10万 m³/s 以上、2 = 1万以上 …（縮尺別表示のための階級） |
| `MAIN_RIV` | 水系の識別子（名前が変わっても同じ水系は同じ値） |

### 指標の選定

- **平均流量**を主指標にする。「大きな川が目に入る」は水の量の話で、
  見た目の川幅とも直結する。`ORD_FLOW` という既製の対数階級があり、
  しきい値をそのままユーザーに見せられる。
- **上流流域面積**は乾燥地で外す（ナイル下流は流域が巨大だが流量は減る）。
- **Strahler order** は支流の本数に反応するので、密に地図化された地域を過大評価する。
- **河川長**は Natural Earth のジオメトリだけで計算でき外部データが要らないが、
  「長い＝大きい」ではない（利根川 > 石狩川 になるが、流量は石狩川が3倍）。

## 対応付け（実測済み）

名前は使わない。**位置だけ**で対応づける。

1. HydroRIVERS の 1 m³/s 以上の reach（2,383,921本）の全頂点を 0.05°（約5.5 km）格子へ落とし、
   セルごとに最大流量の reach を残す → 1,845,538 セル
2. Natural Earth の各頂点について、自セル＋周囲8セル（実効 ±5.5 km 程度）から最大流量を拾う
3. 1本の線につき、頂点ごとの値の**中央値**を採る

中央値が要点。p90 や最大値だと、合流点近くで本流の値を拾って支流が巨大化する。

| 川 | p90 | 中央値 | 実際 |
|---|---|---|---|
| カルカラニャー川 | 19,078 | 27 | 小さい。パラナ川に合流する |
| リシュリュー川 | 10,173 | 447 | セントローレンス川に合流する |
| トンレサップ川 | 13,563 | 1,113 | メコンに合流する |

**結果: 1,455本中 1,449本（99.6%）が対応づいた。** 頂点の被覆はほぼ100%。

対応づかなかった6本: カルカン川（内陸で干上がる）、スエズ運河×2（人工水路）、
ドナウ・デルタの分流1本、無名1本、ロワール川1本。

処理時間はこのPCで約7分（全球1回）。

## 連続性

流量だけでしきい値を切ると、**scalerank より酷く切れる**。上流ほど流量は減るので当然に切れる。

```
しきい値 1,000 m³/s で区間が欠ける川:
  ミシシッピ 1/3   黄河 1/3   ガンジス 0/1   ユーフラテス 0/1   コンゴ 1/2   ナイジェル 1/2
```

対策は2段構え。どちらも既存の仕組みか HydroRIVERS の属性でできる。

1. **同名かつ端点が接する区間は1本の川**とみなし、鎖の最大流量を全区間へ配る
   （いま scalerank に対してやっている昇格と同じ仕組み）
   → ミシシッピ 3/3、黄河 3/3、ナイル 2/2、ナイジェル 2/2、パラナ 3/3
2. 名前が変わる大河（長江＝トゥオトゥオ／金沙江／揚子江）は 1 で救えない。
   **`ORD_CLAS ≤ 2` かつ 水系河口流量 ≥ 20,000 m³/s** を別条件で足す

両方入れると、遠景で欠ける主要河川は無くなる（下表）。

## 段の設計（実装済み）

3段。近景でも全 1,455 本には戻さない。

| 段 | 高度 | 条件 | 本数 | エンティティ |
|---|---|---|---|---|
| 世界 | 6,000 km 超 | 鎖の流量 ≥ 800 または（本流次数 ≤ 2 かつ 水系河口 ≥ 20,000） | 368 | 711 |
| 大陸 | 2,800–6,000 km | ＋ 鎖の流量 ≥ 300 | 662 | 1,208 |
| 国 | 2,800 km 未満 | ＋ 鎖の流量 ≥ 100、または（本流 かつ ≥ 50） | 1,133 | 1,978 |
| — | — | どの段にも入らない（描かない） | 322 | — |

高度は画面に映る範囲で決めた。実測で日本列島が全部入るのが 2,600 km なので、
そこが「国」の段に入るように 2,800 km を境にしている。

描かない 322 本は平均流量の中央値が 34 m3/s 前後の細流。最大でも 99.5 m3/s。
最大エンティティ数は 2,403 → 1,978 に減る。描画は軽くなった。

この設計だと:

- ナイル・チグリス・ユーフラテス・インダス・ガンジス・黄河・長江・アマゾン・
  ミシシッピ・コンゴ・ドナウ・メコン・ヴォルガ・パラナ・オビ・レナ・エニセイ・ライン
  が世界段で全区間つながる
- **石狩川・最上川・利根川が国段で同時に出る**（今までは石狩川だけが2段早く出ていた）
- **トンガリロ川はどの段にも出ない**（32 m3/s、水系河口 373 m3/s）
- 長江の源流トゥオトゥオ川（35 m3/s）は「大水系の本流」として世界段に残る

照合できなかった 7 本（スエズ運河、ドナウ・デルタの分流、干上がるカルカン川など）は
scalerank に落ちる。黙って消さない。

## 説明可能性

総合スコアを作らない。ユーザーに見せる文はしきい値そのものになる。

```
この縮尺では平均流量 800 m³/s 以上の川を表示しています。
利根川は 131 m³/s（石狩川は 294 m³/s）なので、もう少し寄ると出ます。
```

地点の属性には、段とその理由が入っている。

```
利根川      displayTier 3 / displayReason "discharge" / 平均流量 131.5
トゥオトゥオ川  displayTier 1 / displayReason "mainstem"  / 平均流量 35.3 / 水系河口 31,068
スエズ運河    displayTier 3 / displayReason "scalerank" （HydroRIVERS と照合できなかった）
```

`displayReason` が "mainstem" なら、その線は自分の流量ではなく
「大水系の本流だから」残っている。理由を持たせておけば後から文にできる。

## 容量

| 持ち方 | 生 | gzip |
|---|---|---|
| 流量・水系河口・本流次数の3値 × 1,455 | 38.7 KB | **7.7 KB** |
| 流量だけの配列 | 5.5 KB | 2.5 KB |
| 段番号だけの配列（0–3） | 2.9 KB | 0.44 KB |

現在の `rivers.geojson` は 627 KB。3値を全部持っても gzip で **+1.2%**。

段番号だけにすると説明文が書けなくなるので、3値を持つ案を推す。

## 実行時負荷

今: `rank <= maxRank` を段の変わり目に1回、全エンティティぶん。
案: `chainDischarge >= threshold` を同じ場所で1回。**同じ**。

事前に段番号まで焼けば整数1回の比較になり、わずかに軽い。
ランタイムに HydroRIVERS は載せない。読み込むものも増えない。

## Natural Earth に無い川

属性の移植では作れない。3つの選択肢。

1. **受け入れる。** Natural Earth は世界地図用のデータで、国スケールの読みには元々向いていない。
   レンズの断り書きに「主要水系のみ」と書く。
2. **近景の段だけ別ソースで補う。** HydroRIVERS を流量でふるうと
   1,000 m³/s 以上で 61,732 reach（19.6万 km）、100 m³/s 以上で 273,191 reach（86万 km）。
   `MAIN_RIV` で連結して簡略化すれば絞れるが、いまの 627 KB とは桁が変わる。別途設計が要る。
3. **ミッションで日本の川を題材にしない。** 文明のおこり系はナイル・チグリス・
   ユーフラテス・インダス・黄河なので支障はない。

当面 1 と 3。2 は「近景だけ別レイヤ」の設計を別に立ててから。

## 推薦

**C。** 理由は3つ。

1. **説明可能性が段違い。** 「なぜこの川がこの縮尺で出るのか」の答えが
   `平均流量 700 m³/s 以上` という1つの数になる。総合スコアも重み付けも要らない。
2. **アプリが重くならない。** 増えるのは gzip 7.7 KB。実行時の判定は今と同じ1回の比較。
3. **B では足りない。** 長さは流量の代理にならない（利根川と石狩川が逆になる）。
   ただし B の連結計算は C でも使う——鎖の最大流量を配るのに必要。

やったこと:

1. `tools/build-river-importance.py`（オフライン専用。CI では回さない）
2. `public/geo/rivers.geojson` の各 feature に `dis` / `sys` / `clas` / `chain` を焼いた
   （627 KB → 690 KB、gzip 177 KB → 195 KB）
3. `renderer.ts` の LOD を scalerank から流量へ。段は3つ、近景でも全部には戻さない
4. レンズカードの DATA 欄に「数値の出どころ」として HydroRIVERS・引用・ライセンスを追加
5. 日本語の断り書き「河川流量データではありません」は嘘になったので差し替え

残っていること:

- 地点カードの第一声に流量を出すかどうか（いまは属性に入っているだけ）
- `npm run data:geo -- rivers` を回すと派生値が消える。ツールの docstring に書いたが、
  仕組みでは止めていない
- Natural Earth に無い川（信濃川など）は上の3択のまま

`scalerank` は属性として残してある。消す理由がない。
